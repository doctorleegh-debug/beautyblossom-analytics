# 9월 마케팅 전략 시각화 보고서 — 설계

작성일: 2026-08-21
대상 기간: 2026년 9월
근거 데이터 기간: 2026-07-21 ~ 2026-08-19 (GA4 30일)

## 1. 역할과 범위

이 프로젝트는 **상위 전략 레이어**다. 두 하위 산출물을 종합해 익월 마케팅 전략을 만든다.

| 입력 | 출처 | 방식 |
|---|---|---|
| 성과 데이터 | `data/*.json` (GA4·GSC·네이버·YouTube·Instagram) | 읽기 전용. 재수집하지 않는다 |
| 경쟁사 인텔 | Meta 광고 라이브러리 외 공개 소스 | 이 프로젝트가 직접 수집 |

산출물은 `report/strategy-2026-09.html` 한 개다. 월마다 새 파일로 쌓아 지난달 전략의 적중 여부를 되돌아볼 수 있게 한다. 기존 `report/index.html`(성과 보고서)은 건드리지 않는다 — 사실과 해석을 분리한다.

### 2.2 측정 아티팩트 (보고서에 반드시 명시)

GA4 keyEvents는 **2026-07-14부터 측정을 시작**했다. 전기(2026-06-21~07-20)는 부분 측정 구간이므로 keyEvents의 전월 대비 증가율(KR +425% 등)은 전부 아티팩트다. **성장으로 보고하지 않는다.** 당월 구간(07-21~08-19)은 완전 측정되므로 전환율 자체는 유효하다.

## 4. 경쟁사 벤치마킹

### 4.1 대상 정의

홍대 상권 특성상 **글로벌(해외환자 유치) 마케팅에 중점**을 둔다. 대상은 *해외환자를 겨냥해 다국어 유료 광고를 체계적으로 집행하는 한국 클리닉*이며, 수집 결과 7곳을 확정했다.

| 클리닉 | 상권 | 활성 광고 | 타겟 국가 | 운영 페이지 |
|---|---|---|---|---|
| Selenaclinic | 홍대 | 101 | KR·ID·SG·VN·TW·JP·TH | 3 |
| PRIA Clinic | 강남 | 83 | SG·TW·JP | 4 |
| Kleam Clinic | 홍대·명동 | 58 | KR·ID·IN·SG·TW·JP·TH | 3 |
| Cleor Clinic | 홍대·강남 | 45 | KR·SG·TW·JP | 7 |
| 오션클리닉 | 강남 | 28 | SG·TW·JP·TH | 1 |
| ShineBeam | 홍대·강남·강서 | 20 | KR·ID·TW·JP | 4 |
| Primi Clinic | 성수 | 10 | AE·SG·TW | 1 |

Primi Clinic은 성수 소재라 입지 경쟁자가 아니다. 영문 전용 도메인으로 걸프까지 커버하는 채널 운영 사례로만 포함했고, 보고서에도 그렇게 표기한다.

뷰티블라썸의원은 마포구 양화로 66(합정역 3번 출구)이고 Kleam 141·ShineBeam 151·Cleor 165는 홍대입구역 쪽이다. 같은 양화로 축이지만 역세권이 달라 도보 상권은 겹치지 않는다. 경쟁은 오프라인 입지가 아니라 온라인 해외환자 유치에서 일어난다.

### 4.2 "메이저급·광고비 다액" 판정 방법

광고비 실액은 확인 불가하다. Meta 광고 라이브러리는 정치·사회 이슈 광고만 지출액을 공개하며 의료 광고는 비공개다. 따라서 다음 **관측 가능한 대리지표**로 판정하고, 보고서에 대리지표임을 명시한다.

| 대리지표 | 측정 방법 |
|---|---|
| 타겟 국가 수 | 국가별 광고 라이브러리 조회 시 활성 광고가 잡히는 국가 집합 |
| 활성 광고 수 | 광고주별 활성 Library ID 개수 |
| 운영 기간 | `Started running on` 최초 일자 |
| 소재 다양성 | 광고당 크리에이티브 버전 수, 광고주별 고유 소재 수 |

### 4.3 수집 항목

광고주별로 다음을 수집한다. 모두 원본 링크를 보존한다.

- 광고주명, Meta 페이지 ID
- 활성 광고 목록: Library ID, 게재 시작일, 광고 카피 전문, 소재 이미지 URL, 랜딩 URL
- 광고 원본 링크: `https://www.facebook.com/ads/library/?id=<LibraryID>`
- 타겟 국가 집합
- 자사 웹사이트의 다국어 구조 (언어별 서브도메인/경로 유무)

### 4.4 커버리지 한계 (보고서에 명시)

| 항목 | 상태 | 사유 |
|---|---|---|
| 광고비 실액 | 불가 | Meta가 의료 광고 지출액을 비공개 |
| 샤오홍슈 노트 본문 | 불가 | 로그인 월. 검색엔진 경유 시 Q&A 페이지만 노출 |
| Instagram·Facebook 로그인 채널 | 배제 | OpenCLI가 사용자 Chrome을 점유하므로 제약상 제외 |
| 네이버 검색광고 | 부분 | 공개 SERP 관측만 가능 |

## 5. 수집 아키텍처

### 5.1 제약: 사용자 PC 무점유

수집은 사용자의 Chrome·마우스·포그라운드 창을 쓰지 않는다. HTTP 요청과 Anthropic 서버측 실행만 사용한다.

| 경로 | PC 점유 | 용도 |
|---|---|---|
| Jina Reader (`r.jina.ai`) | 없음 | 광고 라이브러리, 경쟁사 사이트 |
| WebSearch / WebFetch | 없음 (Anthropic 서버 실행) | 웹 검색, 정적 페이지 |
| OpenCLI | **점유** | 사용 금지 |
| UIAutomation / 포그라운드 브라우저 | **점유** | 사용 금지 |

### 5.2 광고 라이브러리 응답 상태머신

Jina Reader는 JS 렌더 완료 전에 스냅샷하는 경우가 있다. `x-timeout: 30` 헤더로 렌더를 기다리고, 응답 본문을 다음 세 상태로 판정한다.

| 판정 | 마커 | 처리 |
|---|---|---|
| 결과 있음 | `Library ID:` 포함 | 파싱 |
| 결과 없음 | `No ads match your search criteria` 포함 | 0건으로 확정 기록 |
| CAPTCHA / 레이트리밋 | `requiring CAPTCHA` 포함 | 백오프 후 재시도 |
| 렌더 미완 | 위 셋 다 없음 | 재시도 |

렌더 미완과 "진짜 0건"을 구분하는 것이 중요하다. 구분하지 않으면 경쟁사가 그 국가를 공략하지 않는다고 잘못 결론내린다.

### 5.3 검색 모드 — 탐색과 심층은 다른 모드를 쓴다

광고 라이브러리의 `search_type`에는 두 가지가 있고, 둘을 혼동하면 조용히 틀린 결론이 나온다.

| 모드 | 매칭 대상 | 용도 |
|---|---|---|
| `keyword_unordered` | 광고 **본문** | 탐색 — 어떤 광고주가 이 키워드로 광고하는지 |
| `page` | **광고주명** | 심층 — 이 광고주가 어느 국가에서 광고하는지 |

심층 조회에 `keyword_unordered`를 쓰면 광고 본문에 클리닉 이름을 적지 않는 광고가 전부 누락된다. 실제로 Cleor Clinic이 "전 국가 광고 없음"으로 잘못 집계됐고, 이는 `page` 모드로 바꾼 뒤 45건·4개국·7개 페이지로 정정됐다.

캐시 키에는 반드시 모드를 포함한다. 같은 국가·같은 질의라도 모드가 다르면 다른 결과이며, 키가 같으면 한쪽 모드 응답이 다른 모드에 잘못 제공된다.

### 5.4 광고 카드 렌더 변종

Jina가 반환하는 마크다운에서 광고주명의 위치가 세 가지다. 하나만 가정하면 대량 누락이 난다 — 초기 파서는 648건 중 346건(53%)에서 광고주명을 잃었다.

| 변종 | 광고주명 위치 | 대응 |
|---|---|---|
| 링크형 | `**Sponsored**` 바로 앞 줄의 마크다운 링크 | 링크 텍스트와 페이지 URL을 함께 취한다 |
| 평문형 | `Sponsored` 바로 앞 줄의 평문 | 텍스트만 취한다 |
| 헤더형 | 마커 자체가 없고 아바타 이미지 alt에만 존재 | `s60x60` 썸네일의 alt를 폴백으로 쓴다 |

세 규칙을 모두 적용한 뒤 누락은 25건(3.9%)으로 줄었다. 남은 25건은 라이브러리가 화면 아래를 지연 렌더링해 헤더만 잡힌 카드다.

### 5.5 수집 단계

1. **탐색** — 국가 × 키워드 매트릭스(`keyword_unordered`)로 광고주 후보를 모은다.
2. **필터** — 한국 클리닉만 남긴다. 판정은 랜딩 도메인·광고주명·광고 카피의 지역 언급을 근거로 하며, 각 근거를 기록한다. 자사(Beauty Blossom) 계정과 K-뷰티 제품·콘텐츠 제휴는 제외한다.
3. **선정** — 4.2의 대리지표로 정렬하되, 최종 벤치마크는 명시적으로 지정하고 선정 이유를 기록한다. 자동 상위권에는 클리닉이 아닌 제휴 광고주가 섞이기 때문이다.
4. **심층** — 선정된 광고주를 국가별로 `page` 모드 재조회해 타겟 국가와 운영 페이지 목록을 확정한다.

산출: `data/competitors-2026-09.json`

소재지·다국어 구조는 광고 라이브러리에 없으므로 각 클리닉 공식 사이트를 직접 조회해 `data/competitor-profiles.json`에 출처와 함께 기록한다.

## 6. 보고서 구성

`scripts/build-strategy.mjs`가 `data/*.json` + `data/competitors-2026-09.json`을 읽어 `report/strategy-2026-09.html`을 생성한다. 기존 `build-report.mjs`와 같은 방식으로 JSON을 HTML에 인라인한다.

| # | 섹션 | 내용 |
|---|---|---|
| S1 | 현재 상태 | 시장별 채널 의존도와 전환 효율 (2.1의 사실) |

## 7. 시각화

기존 리포트와 같은 원칙을 따른다: **외부 CDN 없음, vanilla JS + `createElementNS`로 SVG 직접 생성, 단일 파일 오프라인 동작.** Mermaid 등 CDN 의존 라이브러리는 쓰지 않는다.

- 채널 의존도 스택바 (시장별 유료/오가닉 구성)
- 국가 공략 히트맵 (경쟁사 × 국가)
- 경쟁사 광고 운영 간트 (게재 시작일 기준 타임라인)
- 전략 플로우차트 (의사결정 트리)
- 키워드 우선순위 사분면

## 8. 사실기반 규칙

1. 모든 수치에 출처와 수집일을 붙인다.
2. 추정치에는 "추정" 라벨과 근거를 함께 표기한다.
3. 확인 불가한 항목은 공백으로 두고 한계로 명시한다. 추측으로 메우지 않는다.
4. 경쟁사 광고는 원본 Library 링크를 함께 싣는다.
5. 측정 아티팩트(2.2)를 성장으로 표기하지 않는다.
